# [MLOps 실습 시리즈] 8. KFP 파이프라인 준비: MLflow 설치와 컴포넌트 데이터 전달

7편의 판정 로직을 Kubeflow Pipelines(KFP)로 자동화하기 전에 준비한 것들이다.

## 만들 파이프라인

```
서빙 로그 불러오기 → 드리프트 감시
  └ 경보 → 판단 (소량 라벨)
       ├ 보류      → 라벨 추가 요청 알림
       ├ 성능 저하  → 재학습 → MLflow에 후보로 등록
       ├ 재보정     → 판정 기준 재계산
       └ 정상      → 알림만
```

## MLflow를 클러스터 안에 설치하기

KFP 컴포넌트는 클러스터 안의 파드에서 돌기 때문에, MLflow도 클러스터 안에 띄웠다.

| 항목 | 선택 | 이유 |
|---|---|---|
| 기록 저장소 | SQLite + PVC | 혼자 실습하기에 충분하다 |
| 모델 파일 | 기존 MinIO의 `mlflow` 버킷 | KFP 산출물과 한곳에 모인다 |
| 레플리카 | 1개, 교체 방식 `Recreate` | 두 파드가 같은 SQLite 파일을 동시에 쓰지 않게 |

공식 MLflow 이미지엔 MinIO 연결에 필요한 `boto3`가 없어서 이미지를 직접 빌드했다.

설치 후 확인한 것:
- 다른 네임스페이스의 파드에서 `http://mlflow.mlflow.svc.cluster.local:5000` 접근
- 파드를 지웠다 살려도 등록 모델이 남아 있는지

처음 적용할 때 Secret보다 Deployment가 먼저 만들어져서 파드가 잠깐 `CreateContainerConfigError`였다가 스스로 복구됐다. 리소스 사이의 순서도 신경 써야 한다.

## KFP 컴포넌트끼리 데이터 주고받기

컴포넌트는 각자 **별도의 파드**에서 격리되어 돈다. 그래서 변수를 그냥 넘길 수 없다.

| 무엇을 | 어떻게 |
|---|---|
| 작은 값 (판정 결과 문자열 등) | `-> str`로 반환, 다음 컴포넌트에서 `.output`으로 받기 |
| 큰 데이터 (데이터셋, 모델) | `Output[Dataset]`의 `.path`에 파일을 쓰고, 받는 쪽은 `Input[Dataset]`의 `.path`에서 읽기 |
| 지표 | `Output[Metrics]`에 `log_metric` |

큰 데이터는 **값이 아니라 경로로** 넘긴다. 실제 파일은 MinIO에 저장된다.

## 놓치기 쉬운 것 세 가지

**1. `import`는 함수 안에.** KFP는 함수 본문만 떼어서 파드에서 실행한다.

**2. 패키지는 이미지에 미리 넣는다.** `packages_to_install`을 쓰면 파드가 뜰 때마다 설치한다. 이번엔 공용 이미지를 하나 만들고, 7편의 판정 코드 파일도 이미지에 넣었다. 로컬에서 검증한 코드를 복사하지 않고 **같은 파일**을 쓰기 위해서다.

**3. 접속 정보는 파라미터로 넘기지 않는다.** 6장 예제는 MinIO 비밀번호를 파이프라인 파라미터로 넘겼는데, 실행 기록에 그대로 남는다. `kfp-kubernetes`의 `use_secret_as_env`로 K8s Secret을 환경 변수로 연결한다.

## 한 줄 정리

파이프라인은 컴포넌트를 잇는 일보다, 각 파드가 무엇을 어떻게 받는지 정하는 일이 더 많다.
