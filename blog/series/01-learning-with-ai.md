# [MLOps 실습 시리즈] 1. AI와 일하면서 실력 지키기

요즘 Claude와 함께 일하면서 고민이 생겼다. 빠르고 편한데, 어떤 문제에 어떤 도구로 접근할지 스스로 판단하는 힘이 줄어드는 느낌이다. 폐쇄망에서 개발해야 하거나 AI를 못 쓰는 상황이 오면 어떡하지?

그렇다고 AI를 빼는 건 시대착오적이다. 그래서 규칙을 만들었다.

## 원칙: 일할 때와 훈련할 때를 나눈다

조종사는 평소에 오토파일럿을 쓰지만, 수동 비행 시간을 따로 채운다. 같은 방식이다.

| 내가 가져야 할 것 | AI에 맡겨도 되는 것 |
|---|---|
| 문제를 보고 가설 세우기 | 보일러플레이트, 반복 코드 |
| 어디부터 볼지 정하는 순서 | 문법, API 이름 찾기 |
| 1차 도구 감각 (로그, 리소스, 네트워크) | 이미 이해한 작업의 자동화 |
| 답이 맞는지 검증하기 | 문서 요약, 초안 |

## 규칙 다섯 가지

**1. 가설 먼저.** 막히면 AI에게 묻기 전에 두 줄을 쓴다.
```
가설: 원인은 ___ 이다.
근거: ___
```

**2. 학습 세션엔 자동완성을 끈다.** 직접 쓰기로 한 코드를 자동완성이 채우면 연습이 성립하지 않는다. 실제로 그렇게 했다가 힘이 쭉 빠졌다.

**3. 숫자 먼저, 해석은 나중에.** AI에게 결과의 해석까지 먼저 받으면 가설이 너무 쉬워진다. 원자료만 먼저 보고 내 해석을 말한 뒤에 비교한다.

**4. 한 달에 한 번 오프라인 데이.** 네트워크를 끊고, 지난달 AI와 함께 풀었던 문제를 처음부터 혼자 다시 해 본다. 패키지(`pip download`)와 이미지(`docker save`)는 미리 받아둔다.

**5. 채점한다.** 문제마다 내 가설이 맞았는지(O / △ / X), 같은 실수를 반복했는지 기록한다.

## 실제로 해보니

이번 6–7장 실습에서 가설을 다섯 번 세웠다.

| 문제 | 내 가설 | 판정 |
|---|---|---|
| 데이터 다운로드가 멈춤 | openml 서버 문제 | O |
| 자동완성 코드 에러 | (가설 없이 그냥 씀) | X |
| JSON 변환 에러 | `?` 특수문자 문제 | △ |
| 예측 0%는 고장? | 모델이 망가졌다 | X |
| 순이익 규칙이 매일 경보 | 고객층이 바뀐 탓 | O |

적중률은 50%. 숫자보다 의미 있었던 건 4번과 5번이 **같은 유형의 함정**이었다는 것이다. 처음엔 속았고, 두 번째엔 바로 알아챘다.

## 한 줄 정리

AI는 속도를 맡고, 나는 가설과 검증을 맡는다. 귀찮은 날은 쉬어도 된다. 훈련하는 날만 제대로 하면 된다.
