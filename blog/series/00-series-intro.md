# [MLOps 실습 시리즈] 0. 시리즈 소개

《Design a Machine Learning System (From Scratch)》 6–7장을 실습하면서 겪은 일을 한 편에 한 주제씩 정리한다.

실습 시나리오는 하나다.

> 소득 예측 모델(연소득 50K 초과 여부)을 서빙하고 있는데, 마케팅 신규 채널이 열리면서 20대 단시간 근로자가 점점 많이 들어온다. 정답 라벨은 몇 달 뒤에야 도착한다.

이 상황에서 모델을 어떻게 감시하고, 경보가 울리면 무엇을 해야 할지 따라가 본다.

## 목차

| 편 | 주제 | 한 줄 요약 |
|---|---|---|
| 1 | AI와 일하면서 실력 지키기 | 일하는 시간과 훈련하는 시간을 나눈다 |
| 2 | BentoML로 모델 서빙하기 | 요청 한 건은 14열인데 모델은 102열을 원한다 |
| 3 | 드리프트는 어떻게 판정될까 | 열 단위 판정과 데이터셋 단위 판정, 두 단계 |
| 4 | 드리프트 경보 ≠ 모델 고장 | 예측이 0%가 됐는데 정확도는 99%였다 |
| 5 | 경보가 울리면 재학습? | 판정 기준 하나 바꾼 효과가 재학습의 수십 배 |
| 6 | 지연 라벨을 위한 로그 설계 | 고객 ID가 없으면 평가 자체가 불가능하다 |
| 7 | 판정 규칙이 6일 내내 틀렸다 | 지표가 고객층 변화를 성능 저하로 착각했다 |
| 8 | KFP 파이프라인 준비 | MLflow 설치와 컴포넌트 간 데이터 전달 |
| 9 | Kubeflow 노트북 설정 | PodDefault, 어피니티, 톨러레이션 |
| 10 | KFP로 판단 파이프라인 돌려보기 | 경보 후 네 갈래 분기, 사람이 판단할 곳은 남긴다 |

## 실습 환경

- 데이터: UCI Adult (48,842행, 원본 피처 14개)
- 서빙: BentoML 1.1.10 / 드리프트 감시: Evidently 0.5.0
- 파이프라인: Kubeflow Pipelines 2.4 (kind 클러스터) / 모델 관리: MLflow 2.17.2
